# Requirements — `suggest_investments` MCP Tool

## Introduction

Any MCP-connected AI agent (e.g. Claude Desktop, a custom LLM workflow, a Cursor agent) should be able to ask BSpot for AI-generated, personalised investment opportunities — the same results a logged-in user gets through the browser UI — by calling a single tool named `suggest_investments`. This tool wraps the existing `suggestBusinesses` server function and exposes it via the BSpot MCP server so external agents can request real, AI-generated investment opportunities directly.

## Requirements

### Requirement 1

**User Story:** As an MCP-connected AI agent, I want to call a `suggest_investments` tool on the BSpot MCP server, so that I can retrieve AI-generated investment opportunities for a user without requiring them to be in the browser UI.

1. The tool MUST be named `suggest_investments` and listed in the BSpot MCP server's `tools` array in `src/lib/mcp/index.ts`.
2. The tool title displayed in MCP clients MUST be "Suggest investment & business opportunities".
3. The tool MUST be registered by importing and adding it to the `tools` array alongside the existing three tools (`list_countries`, `get_visa_programs`, `estimate_setup_cost`).
4. The MCP server's `instructions` string MUST be updated to mention `suggest_investments` so AI agents discover it and understand its purpose.

### Requirement 2

**User Story:** As an AI agent calling `suggest_investments`, I want to pass a budget, optional country and sector preferences, a risk level, and a time horizon, so that I receive investment suggestions tailored to those constraints.

1. The tool MUST accept a required `budget_usd` number parameter with a minimum value of 100 and a maximum value of 100,000,000.
2. The tool MUST accept an optional `country` string parameter (max 80 characters) for a preferred destination country.
3. The tool MUST accept an optional `sector` string parameter (max 80 characters) for a preferred business or investment sector.
4. The tool MUST accept a required `risk` enum parameter accepting only the values `"low"`, `"medium"`, or `"high"`.
5. The tool MUST accept a required `horizon_years` number parameter with a minimum value of 1 and a maximum value of 30.
6. Inputs that violate any constraint MUST be rejected at the schema validation layer before the handler executes, returning a structured MCP validation error; a `budget_usd` value of exactly 100 MUST be accepted as valid per the minimum requirement.

### Requirement 3

**User Story:** As a BSpot user whose agent calls `suggest_investments`, I want the tool to require my authenticated Supabase session, so that my credits are charged correctly and my data stays private.

1. The tool MUST require a valid Supabase Bearer token; unauthenticated requests MUST be rejected.
2. The MCP server's OAuth layer (`auth.oauth.issuer`) enforces token validation at the transport level; the tool handler MUST rely solely on this layer and MUST NOT add a fallback authentication check of its own.
3. The tool MUST delegate to `suggestBusinesses`, which runs the `requireSupabaseAuth` middleware and constructs a user-scoped Supabase client — the tool MUST NOT bypass or duplicate this middleware.

### Requirement 4

**User Story:** As a BSpot user, I want each `suggest_investments` call to deduct 5 credits from my balance before the AI runs, so that credit gating is consistent whether I use the browser UI or an MCP agent.

1. Each invocation MUST deduct exactly 5 credits via the `consume_credits` Supabase RPC, matching the cost in `suggestBusinesses`; the system MUST verify both that the deduction action occurred and that the resulting balance arithmetic is correct.
2. Credit deduction MUST occur before the AI call (pre-deduction pattern); when credits have been successfully deducted, the AI call MUST be allowed to proceed.
3. If the user has insufficient credits, the tool MUST surface the error `"Not enough credits — this action costs 5."` and MUST NOT proceed to the AI call.
4. The credit deduction MUST be handled by `suggestBusinesses` itself; the MCP tool MUST NOT call `consume_credits` directly, to keep a single source of truth.

### Requirement 5

**User Story:** As an AI agent, I want `suggest_investments` to return 3–5 structured investment opportunities generated by BSpot's AI pipeline, so that I can present them to the user or reason over them further.

1. The tool MUST invoke the same AI pipeline used by the browser UI (`aiToolCall` via `ai-provider.server`, Gemini primary with Groq fallback).
2. The output MUST contain between 3 and 5 `Suggestion` items.
3. Each `Suggestion` item MUST include all nine required fields: `title`, `type`, `country`, `summary`, `est_roi_pct`, `risk_level`, `capital_required_usd`, `steps`, and `risks`.
4. The tool MUST NOT re-implement the AI call, prompt template, or forced tool-call schema — it MUST reuse `suggestBusinesses` to avoid duplication.

### Requirement 6

**User Story:** As an MCP client (plain-text or structured-output), I want `suggest_investments` to return results in a format I can consume, so that both legacy text clients and modern structured-output clients work correctly.

1. The tool response MUST include a `content` array with a single `text` item containing the suggestions array serialised as formatted JSON.
2. The tool response MUST include a `structuredContent` object of shape `{ suggestions: Suggestion[] }`.
3. The tool MUST follow the exact return shape pattern used by the existing tools (`list-countries.ts`, `get-visa-programs.ts`, `estimate-setup-cost.ts`).

### Requirement 7

**User Story:** As an AI agent or developer integrating with `suggest_investments`, I want clear error messages when something goes wrong, so that I can surface a useful explanation to the user rather than a raw exception.

1. Insufficient credits MUST produce the message: `"Not enough credits — this action costs 5."`.
2. AI provider failure (both Gemini and Groq unavailable) MUST propagate the descriptive error message from `aiToolCall`.
3. Any other Supabase RPC error MUST propagate its message.
4. All errors MUST be returned as MCP tool errors (thrown exceptions caught by the `defineTool` runtime), NOT as success responses with an error field; when both a specific message requirement and the MCP error delivery mechanism apply, the MCP tool error delivery mechanism MUST take priority over reproducing exact message text verbatim.

### Requirement 8

**User Story:** As a developer maintaining the BSpot MCP server, I want the new tool to follow the same file and code conventions as the existing tools, so that the codebase stays consistent and easy to navigate.

1. The tool MUST be created as a new file `src/lib/mcp/tools/suggest-investments.ts` using `defineTool` from `@lovable.dev/mcp-js` and `z` from `zod`, matching existing tool imports.
2. The tool MUST be annotated `{ readOnlyHint: false, idempotentHint: false, openWorldHint: false }` because it has a write side-effect (credit deduction).
3. No new npm packages MUST be introduced; all required modules are already present in the project.
4. The tool file MUST export the tool definition as its default export.
